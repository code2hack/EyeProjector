## Objective

Expose Tap, Scroll down, Scroll up, Back, Home, Lock and Mode as seven separate Phone-only HID roles with the correct learning and runtime behavior.

## Scope

- Remove Anchor and combined Back/Lock/Home roles. Tap/Scroll learn only single click. Back/Home/Lock/Mode learn and match short press, long press and multi-click.
- A learned Mode gesture advances the mode once. Complete multi-click dispatch has no early short action. Learning consumes the complete gesture without app effects.
- Preserve ordinary Tap/multi-tap/real hold/drag. Scroll down/up support owned continuous repeat until original UP, Stop, device/route loss or explicit reset; repeats/tails never become a later press.
- Keep Bluetooth controllers on Phone, actual pin/interception, saved identity and ordinary wake/reconnection behavior.
- Explicit compatible migration: retain Tap/Scroll and pin intent; old short Anchor becomes Mode; legacy navigation may preserve single Back, while Home/Lock await explicit assignments. No invented multiple assignments or unrelated reset.
- Own HID classes/resources/tests, HID role DTOs, and the minimal typed merger/caller handoff allocated by Manager. Coordinate-mode models belong to V04-01; final app routing belongs to V04-03. Do not preserve Mode by sending it through the old Anchor registration/Hold interpreter.

## Acceptance

Actual-source learning/gesture/repeat tests cover all seven roles, short/long/multi learning, learning no-output, one final dispatch, duplicate/up tails, repeat stop/loss, Tap hold preservation and saved migration. Report actual timer choices and host/platform boundaries. Root schedules affected Android checks and real Phone-HID/native E2E; host results are not physical proof. Deliver exact draft PR to version/v0.4 and independent review.
