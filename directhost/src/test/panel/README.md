# Active-session panel-power regressions

The additive local API is `PhoneSessionController.requestPanelOff(callback)` / `panelState(callback)`, forwarded through `HostBootstrap` and Binder transactions 5/6 to the existing owned Bridge/Session. These transactions carry expected owner epoch and the actual Session UUID token; host-local replies append both context strings to the existing command fields. Each intent captures its context before the first lifecycle hop, and OFF/query Binder calls run on separate ordinary operation lanes. The lifecycle lane still handles Stop, status, Forget and death. A missing context reports unavailable; it is never discovered later by retargeting the queued intent. A `null` callback result means transport/decoding was unavailable. `PanelSubmission.UNAVAILABLE` means the attached backend had no active streamed session for that request. Neither starts a session. The widget is a separate issue.

`SUBMITTED` means the complete fixed stock message was written locally. OFF and restoration submission are separate fields; `PanelObservation.UNVERIFIED` remains explicit because stock supplies no display-power acknowledgment. The host status exposes `projectionToken` and the final session receipt contains `panelPower`; they cannot prove panel darkness, wakefulness, keyguard state, usable projection or exact foldable-panel restoration.

The panel harness compiles actual production `ShellMain`, `SessionPanelPower`, `PhoneTouchDispatcher`, `HeldInputRelease`, `OwnedRelease` and `LiveScale`. Reflection only arranges the private Session's Android socket/process edges; it executes the real Session request and close methods, and the real Bridge routing/close. Its fourteen scenarios cover Host Stop, Disconnect, failure, never-blanked cleanup, partial OFF failure, cancel/restore exceptions, blocked restore writes, retained Bridge evidence and the existing 250 ms cancellation budget. When cancellation remains blocked, actual transport/child cleanup still finishes, the final receipt says restoration PENDING and physical UNVERIFIED, and a later restoration attempt fails on that old closed socket without touching a new Session. No cleanup budget is extended.

The bootstrap harness executes 23 real adapter scenarios, including the actual SessionController Stop path, blocked OFF and query Binder methods, status/Forget/death progress, stale queued work across same-Binder owner/media replacement, and replacement before the first lifecycle hop. Bridge composition separately verifies exact target capture, admission invalidation before teardown, and rejection of late owner publication/cleanup. The ordinary JVM tests also exercise exact stock bytes, partial OFF failure, repeated OFF, status while a write is pending, whole-input serialization and pinned `keep_active=true` / `power_on=false` / `cleanup=true` startup options. Keep-active remains solely the stock session child's responsibility.

Final scale telemetry samples one nullable immutable reference written only at entry to the existing publish callback. Its basis is UNKNOWN_BEFORE_FIRST_REPORT with null request/geometry/applied fields, or LAST_KNOWN_REPORT_ATTEMPT thereafter. Cached PENDING/REJECTED/older geometry is not final applied success. LiveScale transactions and scale Binder dispatch are unchanged. The overlap regression holds OFF under the control lock while actual LiveScale.request owns its monitor, and requires first/concurrent close and receipt completion before the test releases the OFF latch. Both original reviewed failures and all intervening failed attempts are retained in private evidence.

These are host checks with modeled Android edges. They do not exercise Binder, SurfaceControl, physical devices, an Awake interval or actual stock child teardown. Those acceptance observations require a Manager-granted Phone/Glasses window and separately recorded human judgments. The prior donor endurance failure and unproved per-panel restoration remain unchanged; no pending donor source was imported.
